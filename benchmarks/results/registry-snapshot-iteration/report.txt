Registry snapshot iteration: local JMH comparison
================================================

Upstream base: 743bbab03410082675b1203566ed65a84a5512d6
Baseline: ConcurrentHashMap.newKeySet() membership sets.
Candidate: CopyOnWriteArraySet membership sets; other production source is identical.
Date: 2026-11-13
Host: Apple M5 Pro, 15 logical CPUs, 24 GiB RAM, macOS 26.7.3 arm64.
JDK: OpenJDK 25.0.5 (Liberica); JMH 1.37.

Reproduction
------------
Build identical RegistryBenchmark source against each membership implementation:
  ./mvnw -pl benchmarks -am package -DskipTests -Dcoverage.skip=true
Run each resulting jar sequentially:
  java -jar <variant.jar> RegistryBenchmark -f 3 -wi 3 -i 5 -w 1s -r 1s \
    -prof gc -jvmArgs '-Xms512m -Xmx512m' -rf json -rff <variant.json>

Each case has 3 JVM forks, 3 one-second warmups, and 5 one-second measurements.
Baseline completed before candidate started; the two variants did not compete for CPU.
Both jars contain identical benchmark-class bytecode (hashes in environment.json).
Full JSON includes JMH score errors, confidence intervals, and per-fork raw data.

Benchmark scope
---------------
One thread, one prebuilt gauge family per collector, no optional registration metadata.
This models legacy adapter membership, including the Micrometer MultiCollector path.
Metric construction, sample collection allocation, registration schema validation,
concurrent writers, and application callbacks are not measured.
registerAll is cost per complete registry, using prebuilt collector instances.
registerUnregister is cost per add/remove pair at the stated resident collector count.
scrape includes snapshot construction and sorting. Names are resident_0, resident_1, etc.
The copy-on-write iteration order can favor sorting; read results are workload-dependent.
This is a local comparison, not an isolated CI runner. Small differences need confirmation.

Interpretation
--------------
Copy-on-write avoids mixing old and replacement collector identities within an iteration.
The price is linear membership scanning and array copying on mutations.
Large-registry startup and churn incur substantial time and allocation regressions.
Scraping is faster in this workload, including its insertion-order/sorting effects.
Assess the tradeoff against realistic registry size and collector replacement frequency.
